# Metodo di lavoro

1. Comprendere il compito, il contesto già disponibile e il percorso reale.
2. Identificare cosa è verificato e cosa richiede una decisione o una ricerca.
3. Usare Wayfinder solo se l'iniziativa è troppo incerta per pianificarla responsabilmente.
4. Confrontare alternative quando cambiano davvero l'esperienza o l'architettura.
5. Implementare una parte completa e verificabile, conservando il design esistente salvo richiesta di redesign.
6. Rivedere codice, stati e risultato renderizzato.
7. Aggiornare documentazione e stato senza duplicare gli stessi fatti in più file.

Una skill serve a risolvere una domanda, non è una fase da eseguire automaticamente.
Non caricare tutte le skill per ogni attività.

La ricerca UX distingue ricerca documentale, valutazione euristica e osservazione di utenti reali.
Un agente può preparare test e analizzare dati forniti; non può inventare partecipanti o validazioni.
Scegliere numerosità dei campioni e metriche in base alla domanda: nessuna soglia generica garantisce un risultato.

Per il design, privilegiare un obiettivo principale chiaro senza cancellare informazioni necessarie.
Nella comparazione di varianti cambiare un asse significativo: percorso, gerarchia o densità.
Per il backend, chiarire prima responsabilità dei dati e autorizzazioni.
